# 1. 最重要原則

> **経験によって過去の探索・判断・計算を再利用可能な構造へ変換し、既知処理ほど少ないDecisionで処理する。**

追加条件:

> **Decisionを減らすことと、正しいDecisionを選択することを別問題として扱う。**

低dpcだけを成功としない。

---

# 2. 現行生成系の問題

現在の通常生成は概ね、

```text
入力をsegmentation
↓
最後のUnitをcontext
↓
PredictionStore top-1
↓
次Unitをcontext
↓
繰返し
```

これは実質 next = f(current Unit) の1次的Route選択。

`A → A` や `A → B → A` へ入ると外部停止条件まで継続する。
`ここにここにここに……` `ばばばばば……` はこの構造で説明できる。

---

# 3. Generation State（確定・修正必須）

今後は生成状態を単一Unitだけで表さない。

```text
GenerationState
    current_identity
    current_view
    current_representation
    recent_context        // Ring Buffer
    recent_routes
    emitted_units
    step_count
    no_progress_state
```

---

# 4. Recent Context（確定）

次Routeは P(next | current) だけでなく P(next | current, recent state) 相当の局所情報を参照可能にする。

扱うもの：直近Identity・View・Route・Decision・cycle signature。
短いRing Bufferで十分。Transformerのような全Context走査はしない。

---

# 5. Cycle / No-Progress検出（確定・最優先）

> **計算状態が進展せず同じ局所状態へ戻っている**ことをFailureとして扱う。

検出対象：
- `A → A`
- `A → B → A`
- `A → B → C → A`
- 同一Routeの過剰反復

```text
recent state revisit + new information gain ≈ 0 → no_progress
```

発生時:
```text
現在Routeを一時的に抑制
↓ 次候補
↓ Representation fallback
↓ Recall/generalization
↓ EOS
```

---

# 6. EOS（確定・未実装）

最大N Decision等の強制上限だけを停止機構にしない。

特殊終端状態 `SEQ_END` / `TURN_END` をRoute候補として学習可能にする。

EOS対象は真のsample終端・文/段落終端・会話Turn終端等の意味的境界のみ。
Trainerの任意Block境界をEOSとして学習してはならない。

`max_units`は安全装置として残す。

---

# 7. CompletionとDialogueの分離（確定方針）

```text
GenerationMode::Completion  // 入力続きを生成
GenerationMode::Dialogue    // 入力全体をContextとして別の応答Sequenceを開始
```

Dialogueでは `input末尾Unit → next Unit` だけで最初の応答を決めない。

---

# 8. 入力Echoの分離（修正必須）

現行 `generate_with_trace()` は seed Unit を `generated_units` へ含め全体をdecodeしている。

今後は:
```text
context_units   // 入力
emitted_units   // 出力
```
を分離する。Dialogue Modeの出力は `emitted_units` のみdecode。

---

# 9. Route Candidate Selection（確定・修正必須）

通常生成で無条件Top-1を使用し続けない。局所Top-Kを取得し各候補を評価する。

評価軸：route evidence・context fit・representation fit・recent repetition・cycle risk・feedback

常に局所K候補以内。全Relation走査しない。

---

# 10. 高次Chunk Jumpの制御（確定方針）

> 高次Representationほど適用Contextの一致を要求する。

確認事項：Identity一致・Representation適用可能性・Recent Context整合・Route Evidence

不十分なら細粒度Representationへ Fallback。

---

# 11. Structural LineageとRepresentation Lineageの分離（修正必須）

### Structural Lineage
```text
ABC = AB + C, AB = A + B   // 構造木
```

### Representation Lineage
```text
A/B/C/D/E → A/BC/D/E → AB/CDE → ABCDE   // 処理履歴
```

両者を同一履歴とみなさない。

---

# 12. Representation Fallback（修正必須）

```text
現在使用Representation
↓ その前のRepresentation
↓ さらに細かいRepresentation
↓ Primitive
```

Structural Chunk分解だけでは不足。Representation Lineageから過去処理を復元する。

---

# 13. Route EvidenceとReplay Confidenceの分離（新規修正・重要）

現在ReplayでもPrediction Edgeが強化される。

```text
external_route_evidence    // Experience時に更新
practice_confidence        // Replay時に更新
```

を分離する。Prediction scoreは双方を使えるが意味を混ぜない。

---

# 14. Factorization Pressure修正（修正必須）

現行Context Diversityは diversity↑ → merge threshold実質低下 となっている。

本来は Merge Gain vs Reuse-by-Factorization Gain の比較。

```
NetGain = MergeSaving - FactorizationReuseValue - StorageCost - RedundancyCost
```

`犬は`/`猫は`/`私は` を学習した際、`は` の再利用性が単一巨大Chunkを固定する方向ではなく分離維持する方向にも働くべき。

---

# 15. Cross-View Identity（部分実装）

Union-Find機構は使える。自律的同一性学習は未完成。

```text
candidate identity binding
↓ evidence accumulation
↓ stable identity binding
```

証拠候補：Exact match・Context correspondence・Substitution consistency・cycle consistency・explicit equivalence・feedback

---

# 16. Transform修正（修正必須）

```rust
Transform {
    source,
    target,
    value,       // 追加
    evidence,    // 追加
    origin,
}
```

可逆Transform について T^-1 を数値的に扱えるようにする。log-domain採用時: INV(x)=-x, COMPOSE(x,y)=x+y

---

# 17. TransformとIdentity Mergeの分離（修正必須）

現行 `TransformStore::register()` はTransform登録時に即 `merge_identities(source,target)` している。今後は禁止。

```rust
TransformKind::EquivalentView  // → merge可
TransformKind::Mapping         // → merge不可
TransformKind::Derived         // → merge不可
```

Identity mergeを起こしてよいRelationだけがmergeする。

---

# 18. Unified Relation Core（修正必須）

将来的に以下どちらかへ固定:

**方針A（推奨長期目標）**: RelationStoreを正本とする。Prediction/Recall等はIndex/View。
**方針B**: 各用途Storeを正本とし、共通操作Traitだけ統一。

現在のような無条件二重保存は避ける。段階移行でAへ。

---

# 19. 全体Active Memory Budget（新規確定）

個別に Route K / Recall K / Adjacency K / ... と増やさない。

```text
ACTIVE MEMORY PIE = fixed maximum
```

中を各用途で共有する。

---

# 20. Budget対象と対象外

### Budget対象外（消してはいけないCore）
```text
Stable ID・Primitive・Chunk left/right・View→Identity binding
primary lineage pointer・persistent external address
```

### Budget対象（Active Overlay）
```text
HOT Route・HOT Recall・HOT Adjacency・temporary Candidate
recent context・active feedback overlay・shortcut cache
```

> **存在そのものは残すが、即時アクセス権には上限を設ける。**

# 25. Budget超過時

```text
弱い / 古い / 重複したActive Relation → SLEEP / Coldへdemote
```

完全削除対象は「一時Candidate / 再構成可能 / Evidence極小 / 永続価値なし」に限定。

EvictionScore例:
```
KeepValue = Usefulness + Confidence + Recency + Reuse - MemoryCost - Redundancy
```

# 28. HOT/SLEEP物理分離（修正必須）

現状はRecognition indexが分離しただけでChunk本体は同一struct。

```text

```

# 30. Variable-width ID（codec実装済・統合未完）

binary snapshot / journal / cold storage で実際に使用する。

# 31. Stable ID / Local ID

Stable Global ID → Region/Arena → Local Runtime Index

# 32. Fixed Point（未実装）

現在の f64 runtime → f32 persistence はFixed Pointではない。

Fixed Point化は精度許容値・overflow・saturation・round-trip・generation差を評価してから導入する。

# 33. Micro-ISA（プロトタイプ）

現在VMは存在するが通常推論は通っていない。

仕様上は「Semantic operationの安定した中間契約」とする。Hot PathではRust direct call/inlineへcompile可能。

# 34. Generalization（プロトタイプ）

# 42. 改訂後の生成フロー

```text
Input
↓ Recognition / segmentation
↓ Identity resolve
↓ Generation State構築 (current Identity / View / recent context)
↓ Local Route Top-K
↓ Context / cycle / confidence評価
↓ best viable candidate
   ├─ 成功 → emit
   ├─ no-progress → alternate route
   ├─ confidence不足 → Representation fallback
   ├─ direct不足 → Recall / Generalization
   └─ 終了適切 → EOS
↓ Recent Context更新
↓ 次Decision
```

---

# 43. 改訂後のMemory構造

```text
Permanent Minimal Core
    Stable IDs / Primitive / Chunk Core / Identity anchor
    View binding / Primary lineage
          ↓
Global Active Budget
    Route / Recall / Adjacency / Candidates / Recent Context / Shortcut cache
          ↓
Cold / SLEEP
          ↓
External Memory
```

> 知識量と即時処理量を分離する。Global/Local Budgetが一定なら通常処理はその範囲から大きく外れない。
